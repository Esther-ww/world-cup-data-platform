## 2 技术架构

- PHP 8.1+，PDO，无第三方框架；前后端同源，服务端渲染。
- 默认 SQLite 演示库（`var/demo.sqlite`）；通过 `C_DSN` 可切换 MySQL 8。
- 统一 UTF-8；比赛时间以 UTC 存储和展示，页面注明。
- 目录：

## 3 数据库设计

### 3.1 C 负责的表（MySQL，见 `data/install.sql`）

| 表 | 主要字段 | 关键约束 |
|---|---|---|
| `teams` | id、name、name_en、country_code | country_code UNIQUE |
| `players` | id、name、name_en、birth_date、nationality、position | position ∈ GK/DF/MF/FW；name 索引 |
| `squads` | competition_id、team_id、player_id、shirt_number | PK(competition,team,player)；UNIQUE(competition,team,number)；UNIQUE(competition,player) |
| `lineups` | id、match_id、team_id、formation | UNIQUE(match_id,team_id) |
| `lineup_players` | lineup_id、player_id、is_starter、position、x、y | PK(lineup,player)；is_starter ∈ {0,1}；坐标 0–100 |

依赖成员 B 的 `competitions(id)`、`matches(id)`，两者主键必须为 `INT UNSIGNED`。
`matches` 删除时级联删除 `lineups`，再级联删除 `lineup_players`；球队/球员被引用时限制删除。
“首发 11 人、恰好 1 名门将、球员属于该队该届名单、每队首发不重复”由应用层校验。

### 3.2 独立演示占位表

`data/demo/schema.sql` 额外创建 `users`（A 的占位）、`competitions`、`matches`（B 的占位）。
这三张表**只用于 C 的独立演示与自动化测试**，不得导入正式库。

### 3.3 数据来源与范围

- 2014 年巴西世界杯 A/B 两组：8 队、每队 23 人、12 场小组赛。
- 来源：openfootball 的 `world-cup`、`worldcup.json`、`players` 三个仓库（CC0）。
- 采集日期：2026-11-12；字段说明、转换规则、缺口见 `data/import/README.md`。
- 刻意保留的边界样本：最后 2 场比赛没有阵容；12 名球员没有出生日期；替补只覆盖登场替补。

## 4 路由与权限

| 路由 | 方法 | 权限 | 说明 |
|---|---|---|---|
| `?p=teams` | GET | 公开 | 球队列表与搜索 |
| `?p=team&id=` | GET | 公开 | 球队详情、名单、本届比赛 |
| `?p=players&q=&team=&position=&page=` | GET | 公开 | 球员搜索/筛选/分页 |
| `?p=player&id=` | GET | 公开 | 球员详情与阵容出场记录 |
| `?p=matches` | GET | 公开 | 演示比赛列表 |
| `?p=lineup&match=` | GET | 公开 | 双方阵容；无阵容显示空状态 |
| `?p=auth` | GET | 公开 | 管理员登录（占位账号模块） |
| `?p=admin&tab=team/player/squad/lineup/import` | GET | 管理员 | 后台标签页 |
| POST `teamSave/teamDelete/playerSave/playerDelete/squadAdd/squadDelete/lineupSave/lineupDelete/import` | POST | 管理员 + CSRF | 写操作 |

权限在服务端判断：所有后台 GET 和写操作先检查 `users.role = 'admin'`，普通用户得到 403；
登录成功重新生成会话 id，退出清空会话；所有 POST 校验 CSRF 令牌。
输入统一由控制器校验：长度、正整数、日期、枚举、国家代码；SQL 全部参数化；输出统一 `c_h()` 转义。

## 5 后台与校验规则

- 球队：名称 ≤80、代码 3 位大写字母且唯一；有名单/阵容/比赛的球队禁止删除。
- 球员：姓名 ≤100、国籍 ≤60、位置枚举、出生日期可空但必须是合法过去日期；被名单/阵容引用时禁止删除。
- 名单：球员/球队/届次必须存在；号码 1–99；同一届次球员只能属于一队；同队号码唯一；
  已被阵容使用的球员不能直接移出名单。
- 阵容：
  - 首发正好 11 人；恰好 1 名门将；替补最多 12 人；
  - 球员必须属于本队本届名单，同一球员不能重复；
  - 阵型可留空，留空时按首发位置推算；手填必须是 3–4 段数字且合计 10；
  - 保存后前台立即生效；撤下后前台显示“阵容未公布”。
- CSV 导入：表头必须完全匹配；先逐行校验主键、外键、枚举、日期、号码、阵容人数，全部通过后在一个事务内写入；
  任一行失败整批回滚。后台和 CLI 共用 `PlayerModel::importFile()`。

## 6 测试与证据

测试命令：

```bash
python tests/c_smoke.py /path/to/php
```

覆盖内容（最近一次执行通过）：

- 访客可浏览球队/球员/比赛/阵容；不存在资源返回 404；后台返回 403；
- 球员姓名搜索、球队+位置筛选、分页；
- 无阵容比赛显示“阵容未公布”；
- 普通用户登录后仍不能访问后台；
- 管理员登录、错误 CSRF 被 403 拒绝；
- 球队/球员创建、删除；被引用数据删除返回 422；
- 名单重复号码返回 422；添加/移出名单；
- 阵容 11 人校验（10 人返回 422）、保存后前台同步、撤下后恢复空状态；
- CSV 导入 `--dry-run` 校验通过但不落库，正式导入 8 支球队；
- 退出后不能继续访问后台。

测试使用仓库内临时 SQLite 库和临时会话目录，不修改 `var/demo.sqlite`。

## 7 与 A/B 的集成接口

1. **账号（A）**：删除 `data/demo` 中的 `users` 占位，复用 A 的 `users`、会话与 CSRF；
   C 的控制器只依赖 `$_SESSION['uid']` 和 `users.role`，不接收前端传入的 user_id。
   独立的登录页与 `bin/setup.php admin` 届时移除。
2. **赛事（B）**：用 B 的真实 `competitions`、`matches` 替换占位表；`squads.competition_id`、
   `lineups.match_id` 引用 B 的主键。C 的球队 `teams.id` 需要与 B 的赛程、统计、事件中的球队 id 对齐。
   集成时重新生成或映射 `data/import/squads.csv`、`lineups.csv` 中的 id。
3. **收藏（A）**：A 的 `favorite_teams.team_id` 引用 C 的 `teams.id`；A 的球队目录视图
   `a_team_catalog(id,title)` 可直接取 `teams.id`、`teams.name`。
4. **比赛详情（B）**：B 的比赛详情页可嵌入 C 的阵容组件；共享视图/数据时调用
   `PlayerModel::lineupFor()`、`lineupPlayers()`，或直接链接 `?p=lineup&match=`。
5. **install.sql**：C 的表定义已放在 `data/install.sql`，B 汇总时把文件内容合并到全队安装脚本，
   保留对 `competitions`、`matches` 的外键与索引。
